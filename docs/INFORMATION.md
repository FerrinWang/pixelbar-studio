# 基础信息组件

## B站粉丝数

拖入「B站粉丝数」→ 右侧填写 UID → 点击「读取当前 UID 的粉丝数」，无需先保存。顶部刷新也读取当前草稿中的 UID；预览账号暂存两分钟，不修改已保存场景，也不直接推送设备。保存场景后后台继续采集。

默认 88×24 像素，左侧小电视图标，后面完整数字，不转成万/百万。「显示标题文字」默认关闭；标题文本框保留并支持中文自定义。数字会按宽高降低整数字号倍数；极小的元素仍无法容纳所有数字，请保留足够宽度。七位、八位和最大安全整数的完整渲染有自动测试。

图标与数字支持小/中/大号：图标分别为 7×7 简化版、原有 12×11、18×16 细节版，数字目标倍数为 1/2/3。切换预设立即适配素材框；读取前预留八位数字，避免占位符导致尺寸过小。大号标题用12px字库，小/中标题用10px字库。既有组件没有预设属性时继续沿用原有 scale。

### 编辑三档小电视图标

选择 B站组件 →「编辑小／中／大号图标」。三档分别点画或拖动画笔/擦除，支持撤销、清空本档、恢复本档默认和实时三档预览。固定原生尺寸，不做抗锯齿缩放。「取消」或 Esc 丢弃未应用的修改；「应用到当前组件」只写入当前网页草稿，再保存场景供后台使用。图标存储在该组件 `props.iconOverrides` 的 small/medium/large 二进制行字符串里；其他组件和默认素材不受影响。

图标 JSON 导入/导出包含三档，可跨组件、跨机器复用；文件限制16KB，逐档验证尺寸和0/1像素。导入只修改编辑器草稿，应用后才写入组件。不发送网络请求、不发布到公共页面，也不直接上传设备。预览数字是固定排版示例，不是实时粉丝数。

## 通用素材框

所有素材在编辑器内显示范围框；这些辅助线不包含在导出或设备画面中。「屏幕显示像素边框」单独控制1px实线，内侧保留1px空隙。「框适配内容」一次调整尺寸；勾选「框自动适配内容」后随文字或数据变化调整。默认均不改变旧场景。超出256×32会提示，请缩小字号或精简内容。图形的绘图区域保留已有宽度，文字/图标/图片按原生内容尺寸适配；旧保存点阵不重新生成。

公开接口：`https://api.bilibili.com/x/relation/stat?vmid=UID`。成功数据缓存60秒，最多同时采集三个账号；手动重试失败请求至少间隔5秒。没有账号时不发请求；不需要登录，不收集粉丝名单。接口非本项目控制，可能限流或变更，失败保留上次数字并标记旧数据；首次失败显示 `--`，不会伪造为零。右侧读取按钮会显示错误。

网络传输使用 macOS 自带的 `/usr/bin/curl`，继承用户现有 HTTPS 代理环境，不修改代理设置、不关闭证书校验。其他平台需安装 curl。地址固定为 B站公开统计接口，不接受任意 URL。

本地验证 UID `163637592`：一次真实响应为 `13038226` 粉丝（运行时会变化）。该 UID 只用于独立测试场景，不是用户组件默认值。

## 其他 App 文字通知

拖入「文字通知」，填写频道（默认 `general`），选择字体，保存场景。消息由本地 HTTP API 接收，网页和后台都使用同一份中文点阵字库。

```sh
node scripts/notify.mjs --channel general --title "构建通知" --ttl 60 "构建完成！"
```

要求 Node≥20.11，伴侣已启动。支持 `PIXELBAR_PORT` 选择本地端口；脚本临时建立本机会话，不打印或落盘会话凭据。代码也可以直接发送：

App 亦附带 `Contents/Resources/integration/notify.mjs` 及此说明；可用 App 内的 `Contents/Resources/runtime/node` 运行，不要求另外安装 Node。

```json
{"channel":"general","title":"构建通知","text":"构建完成！","ttlSeconds":60}
```

路径 `POST /api/notifications`；先 GET `/` 获取会话 cookie，后续携带，见 API.md。请求成功表示已接收，不代表硬件已经完成上传。

- 每个频道只显示最新消息，最多8个有效频道。
- 标题最多64字符，正文1–256字符，有效期5秒–24小时，默认60秒。
- 只在内存保存，伴侣重启后清空。不会读取系统通知或第三方私人消息。
- 中文自动换行，长内容末行省略，不滚动；到期恢复「无消息时显示」。
- 开启自动推送才自动更新已保存场景，关闭时只更新网页预览，需手动推送。未保存的通知组件不会出现在后台画布。
- 自定义画布上传提示仍由固件决定，不能承诺实时、无提示或精确到期；忙碌时可能等下一轮15秒更新。

这两项均通过普通插件实现：`web/plugins/bilibili-fans.js`、`notification.js`。数据采集独立于元素排版；其他开发者可复制此结构增加信息插件。
