# 独立重置倒计时与后台条件提醒

## 独立组件

工具箱“Codex 重置倒计时”是 `codex-reset` 元素插件，不是用量组件的一部分。选择5H、WK或两者，倒计时/日期/时间及窗口标签各自可开关；默认内容适配，可加边框、单独拖动和调字号。添加前使用独立配置预览，确认后才加入场景，保存后供后台使用。原用量组件内的重置字段保持不变。

数据来自真实配额的 `resetsAt`，支持Unix秒/毫秒，日期时间使用本机时区，倒计时精确到分钟；缺少数据为 `--`，不编造时间。开启过多字段或过大字号可能裁切，预览提示超出256×32。

## 提醒设置

在“设备与灯光”页下方“Codex 条件提醒”设置。预置5H/WK各两条规则：重置前5分钟、重置时，全部默认关闭。可增加/删除规则（最多20条）、修改窗口、提前分钟数（1–10080）和推送文字。点击“保存提醒设置”后后台生效，保存本身不立即测试推送。

规则独立于自动画布推送开关。网页关闭仍检测，伴侣退出停止。后台每15s采集后检查，受采集和USB队列耗时影响，不承诺精确到秒。只在额度live且设备空闲、连接正常时处理；缺失/失败/过期数据不会生成虚假提醒。

提前提醒：新鲜数据进入指定分钟区间即触发，第一次启用时如果已在区间内也可能触发。已过重置点不补发“即将重置”。重置提醒：以此前观察到的重置时间为基准，即使上游返回下一窗口时间也能识别旧周期到期；第一次启动不会追溯未知历史。重置后15分钟内允许补发错过的提醒，超过不追溯。离线很久、窗口数据跳变及上游时间变化可能造成漏报，不把它当成权威配额重置通知。

同一规则ID/重置周期去重，记录跨重启保留；修改文字/提前分钟数不重新发送同周期已完成规则，新建不同ID则是另一规则。普通失败会在后续检测时重试，成功后不重复。发送前先持久保留去重记录：强制终止/断电可能漏掉一次已保留但未发送完成的提醒，以避免重启后重复发送。不能承诺断电场景exactly-once。

提醒复用已实测的静音新闻＋画布上传流程：暂时关闭消息音并读回 → 用提醒文案替代更新提示 → 等待约1.5s → 同步已保存画布 → 恢复提示音并读回。当前只有静音提醒选项。总驻留由固件控制，提醒不是任意像素叠层；每次提醒伴随一次画布上传，手动模式下也会显示已保存画布，不是未保存草稿或最近单独播放动画。蓝牙音/音量/灯光不修改；断线/强退不能保证临时提示音恢复。

“测试推送”使用已保存规则，会提示确认并真实发送、同步已保存画布；规则未启用也可测试。测试不会消费自动周期去重记录。请勿在设备被TempoHub占用或上传期间测试。

## 数据与API

- 状态目录 `reminders.json`：v1规则。
- `reminder-runtime.json`：已观察窗口、待重试事件及最多200个发送保留记录，与场景独立保存。
- `GET /api/reminders`：`{version:1,rules,status:{lastSent,error}}`。
- `PUT /api/reminders`：`{version:1,rules:[{id,enabled,window:'primary'|'secondary',trigger:'before'|'reset',minutes,text}]}`。
- `POST /api/reminders/test`：`{id}`；成功表示静音更新事务完成，最终视觉效果仍需用户确认。
- 所有接口使用现有本机cookie、Host/Origin保护，推送使用串行HID流程。不要发布用户规则/运行状态文件。

## 提示文字限制

更新提示与提醒文案统一采用：中文/其他非ASCII宽字符最多15，ASCII最多32；英文上限来自大写实测，小写/数字暂沿用预算。混排预算为ASCII×15＋非ASCII×32≤480，是保守近似，不是固件字宽测量。不自动截断，保留空格；不支持控制字符，仍检查255协议字节及引擎E7实际容量。网页、API和Swift入口一致。

旧超长更新提示文件不会被清空或重写，界面允许读出修改；新上传会明确拒绝超长文案，需手动缩短后保存。不要把读取旧配置成功理解为该文本可继续推送。
